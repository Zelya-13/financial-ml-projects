# Прогноз ежедневного денежного остатка

**Описание задачи:** банк/финансовая организация хочет прогнозировать, сколько наличных денег (или денежного остатка) будет необходимо или будет оставаться ежедневно, чтобы управлять ликвидностью, запасами в кассах или банкоматах. У нас есть история операций: снятия наличных, депозиты, остатки, дата (и время), день недели, флаги праздников/выходных.

**Задача:** предсказывать денежный остаток (или аналог — баланс, доступные средства) на конец каждого дня на горизонте 14 дней вперёд.

**Метрики оценки качества прогнозов:**

- sMAPE (симметричная средняя абсолютная процентная ошибка)
- RMSSE (корень из среднеквадратичной ошибки скользящей шкалы)

**Данные:**

- История операций: снятия наличных (`Total_Withdrawals`), поступления (`Total_Deposits`)
- Дата, день недели, время суток
- Календарные особенности: праздничные дни (`Holiday_Flag`), выходные (`Special_Event_Flag`)
- Место произведения операции (например, заправка, торговый центр)

**Особенность данных:** датасет синтетический, что установлено в ходе исследования. Основания:

- отсутствие тренда, сезонности и автокорреляции на всех лагах до 35
- каждый из 50 банкоматов числится во всех 5 типах локаций, причём локация меняется внутри одного дня
- `Previous_Day_Cash_Level` различается у одного банкомата в одну дату, хотя по смыслу это одна величина
- целевой признак линейно вычисляется из `Total_Withdrawals` и `Total_Deposits`: коэффициент при снятиях 1.009, R² = 0.86, остатки симметрично распределены вокруг нуля

**Дополнительное ограничение:** на один банкомат приходится около 113 записей из 731 дня (15% покрытия) с нерегулярными пропусками и несколькими записями за одну дату.

**Что сделано:** изменил тип данных в Date с str на datetime, проверил категориальные столбцы на неявные дубликаты. Затем подготовил данные для экспериментов:

- рассчитал календарные признаки от целевой даты (Date + 1 день), поскольку целевое относится к следующему дню
- исключил признаки, не сохраняющие свойств сущностей (Location_Type, Nearby_Competitor_ATMs, Previous_Day_Cash_Level, Weather_Condition)
- агрегировал данные по датам для проверки временной структуры на полном ряде
- реализовал метрики sMAPE и RMSSE

**После чего провёл пять экспериментов:** прогноз на агрегированных данных на горизонте 14 дней и 1 день, прогноз по неагрегированным данным для отдельных банкоматов, прогноз суммарного дневного спроса, прогноз с операционными признаками. В каждом эксперименте сравнивал линейную регрессию и LightGBM с тремя baseline-моделями (константной, наивной, сезонно-наивной) через TimeSeriesSplit. Для интерпретации построил графики важности признаков и SHAP.

**Результат:** ни одна модель не превзошла константный прогноз ни в одной из пяти постановок — различия между моделями и baseline лежат в пределах разброса метрик по фолдам. Прогнозирование на горизонт 14 дней на этих данных невозможно принципиально: временной структуры в них нет, а целевая переменная вычисляется из признаков той же строки.

Модель с операционными признаками улучшает RMSSE с 0.634 до 0.190, но эти признаки недоступны на горизонте прогноза — улучшение отражает воспроизведение формулы генерации данных, а не найденную закономерность. Интерпретация подтверждает вывод: `Holiday_Flag` и `is_weekend` имеют нулевую важность и нулевой SHAP-вклад, а основной вклад дают признаки с наибольшим числом значений (`dayofyear`, `day`), что указывает на подгонку под обучающие даты.

**Стек** — Python, pandas, numpy, matplotlib, seaborn, scikit-learn, LightGBM, statsmodels, shap.
